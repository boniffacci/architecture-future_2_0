# Описание агрегатов доменов

## Медицинский домен

### Агрегат: Patient (Корневой агрегат)
**Границы**:
- Содержит все данные пациента
- Управляет медицинскими записями и назначениями

**Инварианты**:
- У пациента должен быть уникальный идентификатор
- Обязательные поля: имя, фамилия, дата рождения
- Email должен быть валидным и уникальным

**Ключи**:
- Основной ключ: patientId (UUID)
- Внешние ключи: clinicId, primaryDoctorId

**Состав**:
- Value Objects: PersonalInfo, ContactInfo, InsuranceInfo
- Entities: MedicalRecord, Allergy, ChronicCondition
- Ссылки на: Appointment[], TreatmentPlan[]

### Агрегат: Appointment
**Границы**:
- Представляет запись на прием
- Связан с пациентом и врачом

**Инварианты**:
- Дата приема должна быть в будущем
- Продолжительность приема: 15-120 минут
- Врач должен быть доступен в указанное время

**Ключи**:
- Основной ключ: appointmentId (UUID)
- Внешние ключи: patientId, doctorId, clinicId

### Агрегат: MedicalRecord
**Границы**:
- Медицинская история пациента
- Содержит все посещения и диагнозы

**Инварианты**:
- Привязана к одному пациенту
- Даты записей должны быть в хронологическом порядке
- Конфиденциальные данные должны быть зашифрованы

**Ключи**:
- Основной ключ: recordId (UUID)
- Внешние ключ: patientId

## Финансовый домен

### Агрегат: Account
**Границы**:
- Банковский счет клиента
- Управляет балансом и транзакциями

**Инварианты**:
- Баланс не может быть отрицательным без овердрафта
- IBAN должен быть валидным
- Валюта счета должна соответствовать региону

**Ключи**:
- Основной ключ: accountId (UUID)
- Внешние ключи: customerId, branchId

**Состав**:
- Value Objects: Balance, AccountSettings
- Entities: Transaction[], StandingOrder[]
- Ссылки на: LoanContract[]

### Агрегат: LoanContract
**Границы**:
- Кредитный договор
- Управляет выплатами и процентами

**Инварианты**:
- Сумма кредита: 1000-1,000,000 у.е.
- Процентная ставка: 2-25%
- Срок: 3-360 месяцев

**Ключи**:
- Основной ключ: contractId (UUID)
- Внешние ключи: customerId, accountId

### Агрегат: Transaction
**Границы**:
- Финансовая транзакция
- Перевод между счетами

**Инварианты**:
- Сумма должна быть положительной
- Дата транзакции не может быть в будущем
- Статус: PENDING, COMPLETED, FAILED, CANCELLED

**Ключи**:
- Основной ключ: transactionId (UUID)
- Внешние ключи: fromAccountId, toAccountId

## ИИ-домен

### Агрегат: AIModel
**Границы**:
- Модель машинного обучения
- Версии и метрики модели

**Инварианты**:
- Accuracy должна быть > 70%
- Модель должна быть валидирована
- Дата обучения не может быть в будущем

**Ключи**:
- Основной ключ: modelId (UUID)
- Version: semver (major.minor.patch)

**Состав**:
- Value Objects: ModelMetrics, TrainingParameters
- Entities: ModelVersion[], DatasetInfo
- Ссылки на: Diagnosis[]

### Агрегат: Diagnosis
**Границы**:
- Диагноз, сгенерированный ИИ
- Содержит уверенность и рекомендации

**Инварианты**:
- Должен быть привязан к пациенту
- Confidence: 0.0-1.0
- Диагноз должен быть из медицинской таксономии

**Ключи**:
- Основной ключ: diagnosisId (UUID)
- Внешние ключи: patientId, modelId, doctorId (подтверждение)

## Аналитический домен

### Агрегат: Report
**Границы**:
- Аналитический отчет
- Параметры и данные отчета

**Инварианты**:
- Должен иметь владельца
- Период отчета должен быть валидным
- Данные должны быть актуальными (не старше 24 часов)

**Ключи**:
- Основной ключ: reportId (UUID)
- Внешние ключи: createdBy, templateId

**Состав**:
- Value Objects: ReportParameters, Schedule
- Entities: Chart[], DataTable[]
- Ссылки на: Dashboard[]

### Агрегат: Dashboard
**Границы**:
- Панель мониторинга
- Содержит виджеты и фильтры

**Инварианты**:
- Максимум 20 виджетов на дашборд
- Фильтры должны быть совместимы
- Обновление: real-time или по расписанию

**Ключи**:
- Основной ключ: dashboardId (UUID)
- Внешние ключи: departmentId, ownerId

## Интеграционный домен

### Агрегат: EventRegistry
**Границы**:
- Реестр событий
- Управление схемами и версионированием

**Инварианты**:
- Имя события должно быть уникальным
- Схема должна быть валидной JSON Schema/Avro
- Обратная совместимость при изменениях схемы

**Ключи**:
- Основной ключ: eventName (String)
- Version: integer

### Агрегат: DLQManager
**Границы**:
- Управление ошибочными сообщениями
- Повторная обработка и архивация

**Инварианты**:
- Максимум 3 попытки повторной обработки
- Сообщения старше 30 дней архивируются
- Критические ошибки нотифицируются

**Ключи**:
- Основной ключ: messageId (UUID)
- Внешние ключи: originalTopic, errorType
